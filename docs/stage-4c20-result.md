# 4-C-20 인증 반사 검사 합성 재현·진단 보완

## 범위와 결과의 의미

이전 실제 단건 호출의 `READONLY_RELAY_CREDENTIAL_REFLECTION`은 인증정보 원문 일치와 여러 문자열 조각의 누적 일치를 구분하지 못했다. 원시 응답을 보관하지 않았으므로 당시 원인을 소급해서 확정할 수 없다. 이번 작업은 합성 문자열로 가능한 충돌을 재현하고 이후 실행의 실패 분류를 보완한다. 회사 원본·실제 인증·native·실제 모델·외부 전송에는 접근하지 않는다.

기존 검사는 SSE 전체 JSON 키와 문자열 값을 순서대로 검사하며 무관한 문자열이 사이에 있어도 부분일치 상태를 유지한다. 12자리 가짜 값을 한 글자씩 972개 프레임의 키·값 사이에 배치한 합성 사례는 응답과 개별 문자열에 전체 값이 없어도 거부한다. 마지막 조각 누락과 역순 조각은 통과 대조군이다. 이 재현은 정상적으로 생긴 짧은 문자열 조합도 보수적인 차단 조건을 만족할 수 있음을 보여 주며, 실제 실패가 이 경우였다는 증거는 아니다.

## 구현

- 새 `readonly-relay-reflection-diagnostic-v1`은 `version`, `scope`, `match`, `credential`의 고정 enum 네 개만 담는다. 범위는 `upstream-sse`/`final-json`, 방식은 `raw-exact`/`decoded-exact`/`ordered-fragment`, 인증 종류는 `accessToken`/`accountId`다. 값·조각·길이·위치·프레임 번호·응답 속성명·원문 hash를 담지 않는다.
- 기존 거부 지점에서 private WeakMap에 진단을 결합한다. 현재 동기 응답 검사 안에서 생성한 오류만 전달하므로 transport/reader의 위조 오류나 과거 오류 재생을 현재 검출 증거로 쓰지 않는다. observer 실패는 원래 결과를 바꾸지 않는다.
- broker는 relay-v3에서만 최초 진단 하나를 복사·동결한다. native 실행 감사의 기존 `call-report.json`에 진단이 있을 때만 `reflectionDiagnostic`을 추가한다. 파일 종류와 원래 감사 보관 기한은 그대로다. v1/v2 보고서 형식과 reception 11필드는 바꾸지 않는다.
- 원래 raw 검사 → 문자열별 decoded exact → 순서 조각 검사와 인증 종류의 검사 순서, prefix 상태 64개 한도를 유지한다. 오류 코드, profile/config/계획 hash, 요청 본문, 실행·응답·출력 한도, EOF/반사 검사 전 자식 전달 금지는 변경하지 않는다.

`ordered-fragment`는 검출 방식을 나타내며 오탐 판정이 아니다. 진단 부재도 안전 통과를 뜻하지 않는다. 상태 상한 초과, 다른 오류, 구형 profile에는 이 진단이 없을 수 있다. 이 변경은 오탐 가능성이 있는 기존 차단 규칙 자체를 완화하지 않는다.

## 검증

2026-11-19에 현재 설치된 Node `26.12.1`, pnpm `12.16.1`로 실행했다. pnpm 버전 고정·전환·설치 없이 기존 package/lockfile을 유지했다. 최소 환경에서 빈 별도 패키지 설정과 offline 옵션을 사용했으며 native opt-in은 비활성으로 유지했다.

총 실행 약 94.9초의 전체 회귀에서 최초 실행으로 통과했다. 합성 재현은 972개 프레임의 전체 가짜값 부재와 조각 누적 거부, 마지막 조각 누락·역순 통과를 모두 확인했다. 진단 테스트는 getter/임의 필드·과거 오류 재생·observer 실패·두 인증 종류와 세 검출 방식·최초 진단 유지·v1/v2 진단 부재를 검증했다. 독립 코드 검토에서도 기존 차단 조건·요청 hash 입력·보관 파일 종류 변경은 발견하지 못했다.

새 진단의 native 감사 파일 저장을 실제 native 프로세스로 실행하는 검증은 하지 않았다. 가짜 broker의 진단 수집과 기존 call-report 작성/정리 코드 경로 검토를 구분한다. 회사 대상 파일에 접근하거나 수정하지 않았고 외부 모델 호출은 0회다.

소유자 전용 로컬 검증 로그와 집계는 `/private/tmp/harness-reflection-diagnostics-9ats19wg`에 보관한다. 결과 문서에는 실제 질문·회사 코드·계정/토큰 원문·이전 모델 응답을 포함하지 않는다.

## 다음 최소 작업

새 진단으로 실제 실패 분기를 확인하려면 유효한 새 준비·검토한 본문·계정·기한에 대한 별도 단건 승인이 필요하다. 이전 소비 승인은 재사용하지 않는다. 차단 규칙을 조정하려면 기존 계약과 분리한 정책 및 우회 방지 수용 기준을 먼저 검토해야 한다. 이번 합성 재현을 실제 회사 조사 성공이나 비밀정보 노출 증거로 표현하지 않는다.
